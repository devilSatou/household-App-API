# Issue: テストカバレッジのさらなる向上（81% → 90%以上）

## 概要

現在のテストカバレッジは81.0%です。100%は現実的ではありませんが、コード変更を伴う対応で90%以上を目指せます。

## 現状のカバレッジ

| パッケージ | カバレッジ |
|-----------|-----------|
| handlers | 89.0% |
| middleware | 87.2% |
| models | 78.8% |
| **全体** | **81.0%** |

## 対応が必要な箇所

### 1. main関数の分離（優先度: 高）

**対象ファイル:**
- `main.go`
- `cmd/seed/main.go`

**対応内容:**
```go
// Before
func main() {
    // 全処理
}

// After
func main() {
    if err := run(); err != nil {
        log.Fatal(err)
    }
}

func run() error {
    // 全処理
}
```

### 2. DB接続のインターフェース化（優先度: 中）

**対象ファイル:**
- `models/db.go`

**未カバーのエラーパス:**
| 行 | 内容 |
|----|------|
| L29 | 環境変数デフォルト値 |
| L34-35 | `os.MkdirAll` エラー |
| L38-40 | `gorm.Open` エラー |
| L64-66 | ダブルチェックロック |
| L78-79 | ユーザーディレクトリ作成エラー |
| L82-84 | ユーザーDB接続エラー |
| L88-89 | マイグレーションエラー |
| L93-94 | シードエラー |

**対応案:**
- `GetUserDB` をインターフェース化
- テスト時にエラーを注入できるようにする

### 3. ハンドラーのGetUserDBエラーパス（優先度: 中）

**対象ファイル:**
- `handlers/category.go` (75%)
- `handlers/transaction.go` (73-90%)
- `handlers/summary.go` (80-88%)
- `handlers/export.go` (90%)

**未カバー箇所:**
各ハンドラーの `models.GetUserDB(userID)` 呼び出し後のエラーハンドリング

**対応案:**
既存のDI対応ハンドラー (`*_handler.go`) を使用するようルーティングを変更

### 4. GORMのDBエラーパス（優先度: 低）

**対象ファイル:**
- `models/category.go` (75-85%)
- `models/transaction.go` (75-90%)
- `models/user.go` (63-85%)

**未カバー箇所:**
`db.Create()`, `db.Save()`, `db.Delete()` 等のエラーハンドリング

**対応案:**
- モックDBドライバーの導入
- または、エラー注入用のテストヘルパー作成

## 対応しない箇所（理由付き）

| 箇所 | 理由 |
|-----|------|
| `sync.Once` 内部のエラーパス | 並行処理の競合時のみ発生、テスト困難 |
| ディスクフル等の異常系 | 環境依存、CI環境で再現困難 |
| `middleware/auth.go` の X-User-ID 処理 | 開発環境専用機能 |
